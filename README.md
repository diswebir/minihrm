# مینی HRM — سامانه منابع انسانی و استخدام

سامانه‌ای سبک، ماژولار و فارسی برای **جذب و استخدام** + **آزمون شخصیت‌شناسی (MBTI)** + **داشبورد مدیریتی حرفه‌ای**.

- **بدون هیچ وابستگی npm** (فقط Node.js ≥ 18) — مناسب هاست اشتراکی cPanel **بدون SSH**
- معماری ماژولار؛ هر ماژول از پنل مدیریت قابل خاموش/روشن شدن است
- ویزارد نصب گرافیکی: نفر اول وارد شود، **مدیر ارشد** می‌شود و نام کاربری/رمز می‌سازد
- سطوح دسترسی کامل (RBAC) با نقش‌های پیش‌فرض و امکان ساخت نقش دلخواه
- پورتال استخدام عمومی با کد QR، ورود با **کد پیامکی (OTP)** از طریق **IPPanel**
- فرم استخدام ۱۲ مرحله‌ای (بر پایه فایل «فرم استخدام») با ذخیره خودکار و ویرایش کامل توسط منابع انسانی
- آزمون شخصیت‌شناسی ۲۸ سؤالی با تحلیل حرفه‌ای، میزان تناسب شغلی و راهنمای مصاحبه — **نتیجه هرگز به متقاضی نمایش داده نمی‌شود**
- داشبورد، قیف جذب (کانبان)، مصاحبه و امتیازدهی، بانک سؤالات مصاحبه، پیامک، گزارش‌ها و لاگ فعالیت‌ها

---

## ۱) اجرا

```bash
node app.js
```

- پنل مدیریت: `http://<host>:3000/admin`
- ویزارد نصب (فقط بار اول): `http://<host>:3000/install`
- پورتال استخدام: `http://<host>:3000/careers`

متغیرهای محیطی (اختیاری): `PORT`، `HOST`، `HRM_ROOT`، `HRM_LOG_LEVEL`.

### نصب روی cPanel بدون SSH

1. کل پروژه را در پوشه اپلیکیشن آپلود کنید (File Manager → Upload / Extract).
2. **Setup Node.js App** → Create Application:
   - Application root: پوشه پروژه
   - Application startup file: `app.js`
   - Node.js version: ۱۸ یا بالاتر
3. دکمه **Restart** را بزنید و آدرس سایت را در مرورگر باز کنید؛ ویزارد `/install` خودکار نمایش داده می‌شود.

> داده‌ها در پوشه `data/` (JSON) و لاگ‌ها در `data/logs/` ذخیره می‌شوند. از پنل → تنظیمات → **پشتیبان‌گیری** می‌توانید خروجی JSON بگیرید.

## ۲) نقش‌ها و دسترسی‌ها

| نقش | دسترسی |
| --- | --- |
| مدیر ارشد سامانه (`super_admin`) | همه‌چیز، شامل مدیریت نقش‌ها، ماژول‌ها و تنظیمات |
| مدیر منابع انسانی (`hr_manager`) | مدیریت کامل استخدام، کاربران، پیامک، گزارش‌ها |
| کارمند منابع انسانی (`hr_staff`) | بررسی پرونده‌ها، فرم‌ها، آزمون‌ها، مصاحبه‌ها |
| مصاحبه‌کننده (`interviewer`) | مشاهده پرونده‌ها، امتیازدهی مصاحبه |
| کارمند شرکت (`employee`) | دسترسی محدود (داشبورد و پروفایل) |
| متقاضی | فقط پورتال عمومی: فرم استخدام، آزمون، پیگیری وضعیت |

مدیر ارشد می‌تواند نقش جدید بسازد و دقیقاً مجوزها (۵۱ مجوز در ۱۲ گروه) را انتخاب کند.

## ۳) ماژول‌ها

`dashboard`، `jobs` (موقعیت‌های شغلی و QR)، `recruitment` (پرونده‌ها، فرم‌ساز، کانبان)،
`portal` (حساب‌های متقاضیان)، `assessments` (آزمون و تحلیل)، `interviews` (زمان‌بندی، امتیازدهی، بانک سؤال)،
`users` (کاربران و نقش‌ها)، `sms` (IPPanel)، `reports`، `audit` (لاگ)، `settings`، `profile`.

هر ماژول از **تنظیمات → ماژول‌ها** قابل خاموش/روشن شدن است؛ ماژول‌های وابسته به‌صورت خودکار مدیریت می‌شوند.

## ۴) پیامک (IPPanel Edge)

تنظیمات → **پیامک** → زبانه «تنظیمات سرویس»: کلید API، شماره فرستنده، کد پترن پیش‌فرض و «حالت آزمایشی».
تا زمانی که «حالت آزمایشی» روشن است، هیچ پیام واقعی ارسال نمی‌شود و پیام‌ها فقط در لاگ ثبت می‌گردند
(برای تست، کد OTP در لاگ سرور و در «صندوق خروجی» قابل مشاهده است).

## ۵) آزمون شخصیت‌شناسی

- ۲۸ سؤال دوگزینه‌ای (MBTI)، ۱۶ تیپ، ۴ گروه شخصیتی
- تحلیل ابعاد مرزی، سطح اطمینان تفسیر، تحلیل سؤال‌به‌سؤال
- **تناسب شغلی** بر اساس «تیپ‌های آرمانی» هر موقعیت + دلایل، نکات احتیاطی، محورهای مصاحبه
- تفسیر منابع انسانی (جمع‌بندی تناسب) و خروجی CSV
- بانک سؤالات آزمون و متن سؤالات قابل ویرایش توسط منابع انسانی
- نمایش نتیجه به متقاضی به‌صورت پیش‌فرض **خاموش** است (تنظیمات آزمون)

## ۶) ساختار پروژه

```
app.js                 نقطه ورود
src/core/              هسته: HTTP، دیتابیس JSON، احراز هویت، RBAC، قالب‌ها، پیامک، OTP، MBTI، …
src/modules/<key>/     هر ماژول: index.js (سرور) + client.js (کلاینت پنل)
views/                 قالب‌های سرور (admin/ ، portal/ ، layouts/)
public/                CSS/JS ایستا (بدون CDN — فونت وزیرمتن و کتابخانه QR به‌صورت محلی)
scripts/session.sh     گرفتن نشست مدیر برای تست‌های خط فرمان
scripts/dev/           اسکریپت‌های تست توسعه (اختیاری) — راهنما: scripts/dev/README.md
data/                  داده‌ها، لاگ‌ها و فایل‌های آپلودی (در گیت نیست)
```

## ۷) نکات فنی

- ذخیره‌سازی: مجموعه‌های JSON با نوشتن اتمیک (`data/db/*.json`)
- امنیت: کوکی نشست HttpOnly، CSRF با هدر `X-Requested-With: HRM`، محدودیت نرخ روی OTP/ورود، لاگ فعالیت‌ها
- API: پاسخ‌ها در قالب `{ ok: true, data }` یا `{ ok: false, error, fields? }`
- نصب مجدد/شروع تازه: پوشه‌های `data/db`، `data/logs` و فایل `data/config.json` را حذف کنید و `/install` را باز کنید.

# مینی HRM — فاز اول: استخدام و ارزیابی

سامانه فارسی و راست‌چین منابع انسانی برای شروع فرایند جذب؛ با ویزارد نصب، پنل نقش‌محور، آگهی شغلی، فرم استخدام مرحله‌ای، تأیید موبایل با IPPanel و گزارش توصیفی پرسش‌نامه ۲۸ سؤالیِ فایل‌های ارسالی.

## امکانات این نسخه

- **نصب اولیه بدون SSH:** اولین بازدید، ویزاردی برای نام سازمان و ساخت حساب مدیر کل نمایش می‌دهد. ویزارد پس از نصب قفل می‌شود.
- **Node.js بدون وابستگی زمان اجرا:** برنامه با Node.js و کتابخانه‌های داخلی اجرا می‌شود؛ `npm install` وابستگی خارجی لازم ندارد.
- **نقش و سطح دسترسی:** مدیر کل، مدیر منابع انسانی، کارمند منابع انسانی و کارمند شرکت. مدیر کل دسترسی کامل دارد؛ می‌تواند نقش‌های سفارشی با مجوزهای ترکیبی بسازد، ماتریس دسترسی نقش‌ها را مدیریت کند و حساب‌های داخلی را فعال/غیرفعال کند.
- **استخدام:** تعریف موقعیت و وضعیت جذب، نمایش لینک و QR اختصاصی، فهرست و جست‌وجوی متقاضیان، مراحل پیگیری، یادداشت داخلی، خروجی CSV و داشبورد جذب.
- **فرم استخدام مرحله‌ای:** بخش‌های فرم Excel ارسالی شامل اطلاعات فردی، سوابق کار، تحصیلات، زبان، نرم‌افزار، دوره‌های آموزشی، انتظارات، شرایط کاری و معرف؛ عکس اختیاری نیز در مرورگر کوچک‌سازی می‌شود.
- **کنترل فرم:** مدیران مجاز می‌توانند فیلدهای الزامی را انتخاب کنند. نام و نام خانوادگی و صحت کد ملی در سمت سرور نیز اعتبارسنجی می‌شود.
- **ورود متقاضی با OTP:** شماره موبایل ایران، کد یک‌بارمصرف ۶ رقمی، محدودیت تلاش و انقضا. حالت آزمایشی برای توسعه و اتصال سمت سرور به IPPanel Edge API.
- **ارزیابی محرمانه:** ۲۸ سؤال از سند DOCX به‌همراه گزینه‌ها و کلید امتیازدهیِ مطابق متن فرم. گزارش چهار بُعد، شدت گرایش، توضیح کاری، پرسش پیشنهادی مصاحبه و محدودیت‌های ابزار را فقط کاربران دارای مجوز روان‌شناسی می‌بینند.
- **ماژولار:** ماژول‌های استخدام، پرتال عمومی، ارزیابی و ثبت رویداد را می‌توان از تنظیمات خاموش/روشن کرد.
- **طراحی:** رابط RTL، واکنش‌گرا و کم‌اصطکاک با پالت پاستلی و کارت‌های نرم.

## نصب روی cPanel بدون SSH

> Node.js App در cPanel (معمولاً CloudLinux/Passenger) باید برای دامنه یا زیردامنه شما فعال باشد. اگر گزینه **Setup Node.js App** در cPanel وجود ندارد، از شرکت هاستینگ بخواهید Node.js/Passenger را فعال کند.

1. از File Manager یک پوشه برنامه **خارج از `public_html`** بسازید؛ برای مثال `hrm-app`.
2. فایل‌های این پروژه را ZIP کنید و از File Manager در پوشه برنامه Extract کنید. `app.js` و `package.json` باید در ریشه برنامه باشند.
3. در **cPanel → Setup Node.js App → Create Application**:
   - نسخه Node.js: `18.18+` (ترجیحاً 20 یا جدیدتر)
   - حالت: Production
   - Application root: پوشه‌ای که ساختید، مثلاً `hrm-app`
   - Application URL: ترجیحاً ریشه یک زیردامنه مانند `hrm.example.com`؛ مسیر URL را در ریشه همان زیردامنه قرار دهید.
   - Startup file: `app.js`
4. برنامه را از همان صفحه cPanel ایجاد/Restart کنید. پروژه وابستگی خارجی ندارد، بنابراین نصب پکیج با SSH لازم نیست.
5. از قسمت **Environment variables** تنظیم کنید:
   - `NODE_ENV` = `production`
   - (اختیاری) `MINIHRM_DATA_DIR` = مسیر مطلق یک پوشه خصوصی و قابل‌نوشتن خارج از `public_html`، مثلاً `/home/USER/hrm-private`
   - (اختیاری برای نصب زیرمسیر) `APP_BASE_PATH` = مسیر برنامه، مثلاً `/hrm`؛ در حالت زیردامنه ریشه، خالی بماند.
6. برنامه را Restart کنید و نشانی زیردامنه را باز کنید. ویزارد نصب را تکمیل کنید و نام کاربری و رمز مدیر کل را در جای امن نگه دارید.
7. وارد پنل شوید، یک **موقعیت شغلی فعال** بسازید و QR/لینک آن را برای متقاضیان به‌اشتراک بگذارید.

### پیکربندی IPPanel

در پنل مدیریت → **تنظیمات سامانه**:

1. روش ارسال را روی `IPPanel Edge API` قرار دهید.
2. از IPPanel یک Access Key بسازید (User Panel → Developers → Access Keys)، کلید را وارد کنید و شماره فرستنده تخصیص‌یافته را در قالب E.164، مانند `+983000505`، وارد کنید.
3. تنظیمات را ذخیره و ارسال را با یک شماره واقعی آزمایش کنید.

سامانه طبق مستندات Edge از `https://edge.ippanel.com/v1/api/send` با `sending_type: webservice` استفاده می‌کند. کلید API از مرورگر بازخوانی نمی‌شود. در محیط `production` حالت آزمایشی OTP کد را به کاربر نشان نمی‌دهد و برای ارسال واقعی باید IPPanel تنظیم شده باشد. برای راهنمای کامل به [مستندات IPPanel Edge](https://ippanelcom.github.io/Edge-Document/docs/) مراجعه کنید.

## شروع کار پیشنهادی

1. در تنظیمات فرم، فیلدهای ضروری را با کمینه‌سازی داده شخصی انتخاب کنید.
2. نقش‌های HR Manager و HR Staff را بررسی و برای هر فرد حساب جدا بسازید.
3. موقعیت شغلی را با شرح و الزامات روشن ایجاد کنید.
4. QR/لینک همان موقعیت را منتشر کنید؛ متقاضی موبایل را تأیید می‌کند و فرم را مرحله‌ای پر می‌کند.
5. پرونده و مراحل جذب را در داشبورد بررسی کنید. نتیجه آزمون در سمت متقاضی نه در API عمومی بازگردانده نمی‌شود.

## نکته مهم درباره آزمون روان‌شناسی

فایل DOCX شامل ۲۸ پرسش دوگزینه‌ای با چهار محور E/I، S/N، T/F و J/P است. متن و گزینه‌های هر سؤال در پنل قابل ویرایش‌اند؛ نگاشت هر گزینه به امتیاز ثابت می‌ماند تا مقایسه‌پذیری پاسخ‌ها از بین نرود. گزارش از شمارش پاسخ‌های همین پرسش‌نامه و شرح محتاطانه هر محور ساخته می‌شود.

این ابزار **نسخه رسمی یا اعتبارسنجی‌شده MBTI نیست، تشخیص بالینی نمی‌دهد و عملکرد شغلی را پیش‌بینی نمی‌کند**. گزارش فقط باید به‌عنوان یک فرضیه گفت‌وگومحور در کنار شواهد واقعی شغلی، مصاحبه ساختاریافته و معیارهای یکسان استفاده شود؛ نه برای رد یا پذیرش خودکار. نتایج محرمانه‌اند و نباید به متقاضی نمایش داده شوند.

## ذخیره‌سازی و نگهداری

برای این نسخه سبک، داده‌ها در `storage/data.json` (یا مسیر تعیین‌شده در `MINIHRM_DATA_DIR`) نگه‌داری می‌شوند؛ برنامه **هیچ فایل ذخیره‌سازی را از مسیر فایل‌های عمومی ارائه نمی‌کند** و پوشه `storage` نیز محدودیت Apache دارد. دسترسی فایل روی لینوکس به `0700/0600` تنظیم می‌شود.

این ذخیره‌سازی برای فاز اول و یک فرایند Node مناسب است؛ برای چند نمونه هم‌زمان، حجم بالای پرونده یا نیازهای حسابرسی/نگهداری سازمانی، پیش از توسعه بیشتر باید مخزن به MySQL/MariaDB cPanel و نسخه پشتیبان زمان‌بندی‌شده منتقل شود. پوشه داده را منظم و رمزگذاری‌شده در محل خصوصی پشتیبان‌گیری کنید. نشست کاربران با راه‌اندازی مجدد برنامه منقضی می‌شود و کاربران باید دوباره وارد شوند.

نمای QR در نسخه اول از سرویس عمومی QR Server برای **لینک عمومی موقعیت شغلی** استفاده می‌کند؛ اطلاعات شخصی متقاضی در URL قرار نمی‌گیرد. لینک متنی فرم نیز همیشه قابل کپی است.

## توسعه و آزمون محلی

نیازمند Node.js `18.18+` است. برای اجرای محلی:

```bash
npm start
```

سپس `http://localhost:3000` را باز کنید. در حالت توسعه، OTP آزمایشی در پاسخ API و صفحه فرم نشان داده می‌شود. آزمون‌های داخلی:

```bash
npm test
```

داده‌های ایجادشده در `storage/data.json` نگه‌داری می‌شوند؛ برای شروع تمیز، برنامه را متوقف و آن فایل را از پوشه داده پاک کنید. پس از پاک‌شدن داده‌ها، ویزارد نصب دوباره نمایش داده می‌شود.
